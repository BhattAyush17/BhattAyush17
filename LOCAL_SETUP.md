# Running GitHub Stats Generator Locally

## 1. Prerequisites

### Get a GitHub Personal Access Token
1. Go to https://github.com/settings/tokens
2. Click **Generate new token** → **Generate new token (classic)**
3. Give it a name like "stats-local"
4. Check these scopes:
   - ✅ `public_repo` (read public repos)
   - ✅ `read:user` (read user profile)
5. Copy the token (you'll only see it once)

### Clone & Install
```bash
# Navigate to your repo
cd /path/to/BhattAyush17-main

# Install Python dependencies (only requests is required)
pip install -r scripts/requirements.txt
```

## 2. Run the Script Locally

### Option A: With Your Token (Full Data)
```bash
export GH_STATS_TOKEN="ghp_your_actual_token_here"
python scripts/generate_stats.py
```

**Expected output:**
```
10:08:16 [INFO] ✅ Streak self-tests passed
10:08:16 [INFO] ============================================================
10:08:16 [INFO] GitHub contribution fetch
10:08:16 [INFO] User: BhattAyush17
10:08:16 [INFO] ============================================================
10:08:16 [INFO] Requesting LIVE contribution calendar...
10:08:17 [INFO] Cache updated: assets/cache/bhattayush17-github.json
10:08:17 [INFO] LIVE SUCCESS: 1123 ms
10:08:17 [INFO] Current streak: 4
10:08:17 [INFO] Longest streak: 19
10:08:17 [INFO] Last contribution: 2026-10-21
10:08:17 [INFO] Cards written: assets/stats/github-cards.svg
10:08:17 [INFO] ============================================================
10:08:17 [INFO] SOURCE: graphql_api
10:08:17 [INFO] FRESHNESS: just now
```

The script writes the three-card row (`assets/stats/github-cards.svg`), the
commits-by-hour card (`assets/stats/commit-hours.svg`), the standalone cards
(`github-stats.svg`, `languages.svg`, `streak.svg`), `assets/stats/data.json`,
`assets/streak/streak.svg` and the cache file. `cards_svg.py` holds the pure
renderers; `generate_stats.py` does the fetching and file I/O.

`assets/stats/hourly.json` is a committed snapshot of commits per hour (the
GraphQL calendar has no hourly data), so `commit-hours.svg` is labelled
`snapshot` rather than `live`.

`assets/stats/data.json` is the machine readable snapshot used by the HTML
card renderer in `index.html` (the SVG cards cannot be used on a page that
runs JavaScript).

The snake is generated by `Platane/snk`, then post-processed locally:

```bash
python scripts/finalize_snake.py
```

That step adds the month labels and the "Less / More" legend and removes the
animation's progress bar, which otherwise renders as a grey bar under the
graph in still images.

### Option B: Without Token (Cache Only)
If you don't have a token or want to test fallback behavior:
```bash
python scripts/generate_stats.py
```
It will try to use the cache from `assets/cache/bhattayush17-github.json` (created on first successful run). The cache is used as a fallback whenever the live API is unavailable — the card then shows a `cached · <age>` badge instead of `live`.

## 3. Inspect the Output

### Check Generated SVGs
```bash
# List what was generated
ls -lh assets/stats/

# View file sizes (healthy SVGs are > 1 KB)
du -h assets/stats/*.svg

# Validate SVG syntax (should contain <svg xmlns>)
head -1 assets/stats/github-cards.svg
head -1 assets/stats/commit-hours.svg
```

### Open in Browser
```bash
# macOS
open assets/stats/github-cards.svg
open assets/stats/commit-hours.svg
open assets/stats/github-stats.svg
open assets/stats/streak.svg

# Linux
xdg-open assets/stats/github-cards.svg

# Or just drag any .svg file into your browser
```

### Check the Cache
```bash
cat assets/cache/bhattayush17-github.json | python -m json.tool | head -50
```
Should show your real GitHub stats with a timestamp.

## 4. Test Scenarios

### Scenario 1: Fresh Fetch + Real Render
```bash
export GH_STATS_TOKEN="your_token"
rm -f assets/cache/bhattayush17-github.json  # force fresh fetch
python scripts/generate_stats.py
# ✅ Should fetch live, render all cards, cache the data
```

### Scenario 2: Use Stale Cache
```bash
unset GH_STATS_TOKEN
python scripts/generate_stats.py
# ✅ Should load from cache (even if 7+ hours old) and render
```

### Scenario 3: No Token, No Cache (Failure)
```bash
unset GH_STATS_TOKEN
rm -f assets/cache/bhattayush17-github.json
python scripts/generate_stats.py
# ❌ Should exit with error message, keeping old SVGs untouched
```

### Scenario 4: Language Query Times Out
```bash
export GH_STATS_TOKEN="your_token"
python scripts/generate_stats.py
# ✅ The three cards still render from contribution data
# ✅ languages falls back to the committed data.json snapshot
```

## 5. Troubleshooting

### "No module named requests"
```bash
pip install -r scripts/requirements.txt --break-system-packages
```

### SVGs look broken/blank
1. Check file size: `ls -lh assets/stats/github-cards.svg`
   - Should be > 4 KB
2. Check the file starts with an `<svg` tag:
   `head -c 200 assets/stats/github-cards.svg`
3. Check logs for what failed: look at the `[ERROR]` lines in output
4. Re-run with your token to force a fresh render

### Token not working
- Confirm it has `public_repo` + `read:user` scopes
- Test: `curl -H "Authorization: Bearer your_token" https://api.github.com/user`
  - Should return your GitHub user JSON, not `{"message": "Bad credentials"}`

## 6. Before Committing

1. **Run locally and verify visually:**
   ```bash
   export GH_STATS_TOKEN="your_token"
   python scripts/generate_stats.py
   open assets/stats/*.svg  # inspect each card
   ```

2. **Check cache was created:**
   ```bash
   ls -lh assets/cache/bhattayush17-github.json
   ```

3. **Refresh the README text blocks and the image cache busters:**
   ```bash
   # recent repos, pinned repos, achievements, neofetch card, sync stamp
   python scripts/readme_sync.py

   # content hashed ?v= parameters for every local image
   python scripts/bump_versions.py

   # verify (exit code 1 means something is out of date)
   python scripts/bump_versions.py --check
   ```

4. **Commit the SVGs and the cache:**
   ```bash
   git add assets/stats/*.svg assets/streak/*.svg README.md
   git add assets/cache/bhattayush17-github.json
   git add assets/badges/ neofetch_card.svg index.html
   git add -u assets/  # stage deletions if any
   git status
   git commit -m "chore: update README stats [generate_stats.py]"
   ```

5. **Keep the cache committed** — `assets/cache/bhattayush17-github.json` is the
   last-known-good snapshot that CI falls back to when the live GitHub API is
   unavailable. `.gitignore` already un-ignores exactly that file:
   ```gitignore
   assets/cache/*
   !assets/cache/bhattayush17-github.json
   ```

> **Note:** `scripts/generate_stats.py` already calls `readme_sync.sync_all()`
> at the end of a successful run, so step 3 is only needed when you want to
> refresh the README blocks without regenerating the cards.

## 7. Watch Logs in Real Time

To see exactly what's happening as it runs:
```bash
export GH_STATS_TOKEN="your_token"
python -u scripts/generate_stats.py 2>&1 | tee stats-run.log
```

Then inspect the log:
```bash
cat stats-run.log | grep "ERROR\|WARNING\|✅"
```
